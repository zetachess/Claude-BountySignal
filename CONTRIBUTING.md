# Contributing to Claude-BountySignal

Claude-BountySignal welcomes focused improvements that make authorized security testing safer, clearer, and more reproducible.

## Before opening a change

- Keep the change narrowly related to authentication, sessions, recovery, tokens, authorization, or reporting.
- Write new material in your own words and include references where a claim depends on an external standard.
- Never add live credentials, customer data, real session tokens, or undisclosed target details.
- Prefer synthetic examples and intentionally vulnerable practice applications.

## Content standard

Every new check should explain its preconditions, expected control, safe validation approach, evidence requirements, and remediation direction. A payload without a validation model is not considered a complete contribution.

## Pull requests

Describe the behavior changed, the security boundary involved, and how the change was tested. Keep the English version authoritative; translations may follow the same intent without changing the safety boundary.
